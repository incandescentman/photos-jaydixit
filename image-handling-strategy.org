* Image Handling Strategy

This document details the image handling strategy employed in the `photos-jaydixit` repository.

*Last Updated:* 2026-01-06

**Summary:** The project uses a *CDN-first approach* for the homepage (Cloudinary) combined with standard Astro image processing for gallery pages. This hybrid strategy optimizes for fast builds, automatic format negotiation, and edge caching while maintaining simplicity for gallery content.

* 1. Architecture Overview

** Homepage (Cloudinary CDN)
- Images served directly from Cloudinary
- No build-time image processing
- Automatic format negotiation (AVIF/WebP/JPEG)
- Edge caching via Cloudinary CDN
- Simple `<img>` tags with srcset

** Gallery Pages (Astro Image)
- Standard Astro `<Image />` component
- Build-time optimization
- WebP conversion by default

* 2. Homepage Implementation

** Strategy: Cloudinary CDN

The homepage (`src/pages/index.astro`) uses Cloudinary URLs directly instead of build-time processing:

#+begin_src typescript
// Cloudinary configuration
const CLOUDINARY_CLOUD = 'dszpm7yps';
const cldUrl = (publicId: string, width?: number) => {
  const transforms = width ? `f_auto,q_auto,w_${width}` : 'f_auto,q_auto';
  return `https://res.cloudinary.com/${CLOUDINARY_CLOUD}/image/upload/${transforms}/${publicId}`;
};
const cldSrcset = (publicId: string, widths: number[]) =>
  widths.map(w => `${cldUrl(publicId, w)} ${w}w`).join(', ');
#+end_src

** Size Presets

#+begin_src typescript
const sizePresets = {
  portrait: { widths: [400, 800, 1200], sizes: '(max-width: 640px) 90vw, (max-width: 1100px) 45vw, 320px' },
  landscape: { widths: [640, 1000, 1440], sizes: '(max-width: 640px) 100vw, (max-width: 1100px) 90vw, 648px' },
  xlportrait: { widths: [500, 900, 1400], sizes: '(max-width: 640px) 90vw, (max-width: 1100px) 60vw, 648px' }
};
#+end_src

** Benefits
- *Instant builds:* No image processing during build
- *Automatic format:* `f_auto` serves AVIF/WebP/JPEG based on browser support
- *Quality optimization:* `q_auto` automatically optimizes compression
- *Edge caching:* Images cached at Cloudinary's global CDN
- *Simpler code:* No `getImage()` calls, no `<picture>` elements

** Image Storage
- Source images: Uploaded to Cloudinary (folder: `highlights/`)
- Local files: Removed from repo (added to .gitignore)
- Public ID format: `highlights/{filename-without-extension}`

* 3. Gallery Pages Implementation

** Strategy: Standard Astro Component

Gallery pages (`src/pages/gallery/[...folder].astro`) use the standard Astro `<Image />` component:

#+begin_src javascript
import { Image } from 'astro:assets';
<Image
  src={image.metadata}
  alt={image.caption}
  width={w}
  height={h}
  loading="lazy"
/>
#+end_src

** Sizing Logic
- Uses heuristic based on image index for layout variants
- CSS classes: `regular`, `wide`, `wide_tall`
- Responsive scaling via CSS + Packery.js

* 4. Responsive Strategy

** Breakpoints
- *Mobile (<768px):* Single column stack, CSS flexbox
- *Desktop (>=768px):* Packery.js masonry layout

** Homepage
- 3 responsive widths per size category (vs 5 previously)
- Cloudinary generates on-demand
- ~90% reduction in build artifacts

** Gallery Pages
- Fixed dimensions passed to Astro Image
- CSS handles responsive scaling
- Packery.js manages grid layout

* 5. Image Format & Quality

** Cloudinary (Homepage)
- `f_auto`: Automatic format selection
  - AVIF for supported browsers (best compression)
  - WebP for most modern browsers
  - JPEG fallback for older browsers
- `q_auto`: Automatic quality optimization

** Astro (Galleries)
- Default WebP conversion
- Sharp processing at build time

* 6. Metadata Handling

** Filename Convention
Format: `Subject_Event_Year-Tag.jpg`
Example: `vanessa-kirby_toronto-film-festival_2024.jpg`

** Extraction
- `buildCaptionAndTags` function parses filenames
- Optional `tags.json` sidecar files for overrides
- `src/data/image-metadata.json` for dimensions (CLS prevention)

* 7. Key Files

| File | Purpose |
|------|---------|
| `src/pages/index.astro` | Homepage with Cloudinary integration |
| `src/data/homepage-images.js` | Homepage image configuration |
| `src/lib/cloudinary.ts` | Cloudinary URL helpers |
| `scripts/upload-to-cloudinary.js` | Upload script for new images |
| `src/pages/gallery/[...folder].astro` | Gallery page with Astro Image |
| `src/scripts/packeryGallery.ts` | Masonry layout + PhotoSwipe |

* 8. Adding New Homepage Images

1. Add image to local folder (temporary)
2. Run upload script:
   #+begin_src bash
   node scripts/upload-to-cloudinary.js ./path/to/images highlights
   #+end_src
3. Add entry to `src/data/homepage-images.js`
4. Build and test

* 9. Migration History

** Before (Pre-2026-01)
- Build-time processing with Astro `getImage()`
- 5 widths × 2 formats = 10 variants per image
- ~500 generated files for homepage
- `<picture>` elements with WebP + JPEG sources

** After (2026-01-06)
- Cloudinary CDN delivery
- 3 widths, automatic format selection
- Zero build-time variants for homepage
- Simple `<img>` with srcset
- ~200MB removed from repo

* 10. Cloudinary Setup

** Environment Variables
#+begin_src bash
PUBLIC_CLOUDINARY_CLOUD_NAME=dszpm7yps
PUBLIC_CLOUDINARY_TRANSFORM=gallery
CLOUDINARY_URL=cloudinary://<api_key>:<api_secret>@<cloud_name>
#+end_src

** Upload Limits
- Free tier: 10MB per file
- Oversized files: Convert to WebP locally first

** URL Pattern
#+begin_example
https://res.cloudinary.com/{cloud}/image/upload/{transforms}/{publicId}

Example:
https://res.cloudinary.com/dszpm7yps/image/upload/f_auto,q_auto,w_800/highlights/vanessa-kirby
#+end_example
