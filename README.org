* Overview

This is my personal photography portfolio site at [[https://photos.jaydixit.com][photos.jaydixit.com]], built entirely using [[https://claude.com/claude-code][Claude Code]].

The site is built with [[https://astro.build][Astro]], hosted on Vercel, and powered by Cloudinary for image optimization and delivery.

* About Jay Dixit

Hi, I'm Jay Dixit, a science writer, educator, and red carpet photographer.

As a photographer, my goal is to capture natural, spontaneous moments — those raw, unguarded glimpses of laughter, joy, or surprise that reveal someone's personality in a single frame.

As a press photographer for Wikipedia, I've covered The Nobel Prizes in Stockholm and The Nobel Peace Prize in Oslo, red carpets at Sundance, SXSW, the Toronto International Film Festival, and the New York Film Festival, as well as cultural and literary events in New York, San Francisco, and Toronto.

I was the founding photographer of the WikiPortraits initiative and I contribute actively to Wikimedia Commons, where I help expand the public archive of high-quality images from diverse voices and communities.

In my parallel life as a science writer, writing professor, and AI educator, I specialize in storytelling, psychology, and the ethical use of AI to amplify human creativity. I taught storytelling as a writing professor at Yale, and my work has appeared in The New York Times, Rolling Stone, The Washington Post, Wired, Harvard Business Review, and Psychology Today, where I was a senior editor.

Through my company Socratic AI, I lead AI education workshops and training programs for universities and companies. Most recently, I worked at OpenAI, where I led the writing community, spearheading initiatives to help writers and educators use AI as a thought partner to support the writing process.

* Key Technical Notes

** Image Import Solutions for Astro MDX

*** Problem: Images not loading in MDX files
When using ImageGallery components or Image components from Astro in MDX files, you may encounter "image is not defined" errors.

*** Solution: Proper Image Import Pattern

1. *Store images in src/assets folder*
   - Create folder: ~/src/assets/images/[page-name]/~
   - Copy all images to this folder instead of using ~/public/~

2. *Configure path alias in astro.config.mts*
   #+begin_src javascript
   import path from 'path';
   import { fileURLToPath } from 'url';

   const __filename = fileURLToPath(import.meta.url);
   const __dirname = path.dirname(__filename);

   export default defineConfig({
     vite: {
       resolve: {
         alias: {
           '~': path.resolve(__dirname, './src'),
         },
       },
     },
   });
   #+end_src

3. *Import images in MDX using relative or tilde paths*
   #+begin_src javascript
   // Using tilde alias (requires config above)
   import heroImg from '~/assets/images/wikiportraits/hero.jpg';

   // Using relative paths (works without config)
   import heroImg from '../assets/images/wikiportraits/hero.jpg';
   #+end_src

4. *Use with ImageGallery component*
   #+begin_src javascript
   import ImageGallery from '@jaydixit/astro-utils/components/ImageGallery.astro';

   <ImageGallery
     images={[
       { src: img1, alt: "Description 1" },
       { src: img2, alt: "Description 2" }
     ]}
     galleryId="unique-gallery-id"
     columns={2}
   />
   #+end_src

*** Key Learnings
- Always import images as ES modules in Astro MDX files
- Store images in src/assets, not public folder for proper bundling
- Use either tilde alias (with config) or relative paths for imports
- ImageGallery component from astro-utils requires image objects with src and alt properties

*** Troubleshooting Tips
- If "image not defined" error occurs, check:
  1. Image is imported at top of MDX file
  2. Import path is correct (relative or with ~ alias)
  3. File exists in src/assets folder
  4. Variable name matches usage in component

* Philosophy

** Content First, Code Adapts
Photography content is the source of truth:
- *Photos drive the structure* - folder organization determines galleries
- *Metadata in filenames* - captions extracted from filenames
- *Code serves content* - parsers and generators adapt to photo organization
- *Preserve photographer intent* - don't modify photos or organization to fix code

** Static Generation with Dynamic Feel
- Pre-rendered galleries for speed
- Progressive enhancement for interactivity
- Cloudinary for optimization
- Minimal JavaScript for core functionality
