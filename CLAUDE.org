​** Overview

This is a static photography portfolio site built with Astro, hosted on
Vercel at photos.jaydixit.com. It supports automatic gallery generation
from folders, responsive masonry layout, full-screen lightbox viewing,
keyword search, tag-based filtering, per-photo liking, per-person
portrait pages, and optional commenting via Giscus. All metadata is
derived from filenames, per-folder tags.json files, or the people.json
manifest.



​** Core Features



​*** 📁 Folder-Based Gallery Pages

- Gallery source photos live in src/gallery/photos/** folder
- Portrait and homepage highlight assets also live in src/gallery/highlights/

- Each subfolder becomes a separate gallery

- Example: src/gallery/photos/locarno-film-festival →
  /gallery/locarno-film-festival



​*** 🧱 Masonry Layout

- Pure CSS layout with column-count and break-inside: avoid

- Responsive grid that lazy-loads images



​*** 💡 Lightbox Viewer

- *Every page that displays photographs must have working PhotoSwipe for every photograph.* This is a site-wide requirement, including homepages, galleries, person pages, editorial and story pages, blog posts, About pages, comparison pages, and experimental routes.

- Never replace a PhotoSwipe-enabled photograph with a plain image or ordinary image link while changing copy, layout, or image sources.

- A page change involving photographs is not complete until browser verification confirms that the first click opens the correct full-size image, navigation works when the page contains multiple photographs, and Escape closes the lightbox. Verify at desktop and mobile widths and check for browser errors; a successful build alone does not prove PhotoSwipe works.

- Main galleries and comparison pages use PhotoSwipe for full-screen viewing

- Older docs and backups may still mention GLightbox, but live gallery surfaces should stay on PhotoSwipe

- Full-size viewer with zoom and nav arrows



​*** 📑 Captions from Filenames

- Filenames like maria-bakalova_locarno_2024.jpg become:

  "Maria Bakalova at Locarno in 2024"

- Year is optional

- Displayed under each photo



​*** 🔍 Search and Tag Filtering

- Single search input filters by:

  - Subject name

  - Event name

  - Tags (from filename or tags.json)

- Tags also appear as clickable pills (AND logic)

- Search and tags can be used together for progressive narrowing



​*** 🏷 Tags System

- Tags extracted from:

  - Filenames (e.g. _rain-night)

  - Folder names (e.g. /locarno → "locarno")

  - Optional tags.json file per folder

- tags.json format:

  {

  "filename.jpg": ["tag1", "tag2"]

  }

- If tags.json exists, it overrides filename tags



​*** 👤 Red Carpet Photos (Per-Person Pages)

- Each person in src/data/people.json gets a page at /red-carpet/[slug]

- Index page at /red-carpet/ lists all people alphabetically with sample photos

- Legacy /portraits/ routes exist only as redirects to /red-carpet/

- people.json fields: slug, name, match (filename patterns), photoSlugs (optional explicit mappings), bio (optional), wikipedia (optional)

- Match logic: subject slug (part before first _ in filename) checked against match patterns

- Numbered variants supported: match pattern "jeremy" also matches "jeremy-3", "jeremy-11"

- For group photos and non-standard filenames, use photoSlugs for explicit file-to-person mapping (e.g., group-portrait_ana-de-armas-sydney-sweeney-ron-howard_2024)

- Photos scanned from both src/gallery/photos/ and src/gallery/highlights/; gallery sources preferred for dedup

- Highlight-only photos render without gallery detail links

- Index page exclusions: the portraits index only shows people who have at least one solo portrait. Group shots and multi-person photos are automatically excluded — if a photo's filename contains another person's slug from people.json, it is skipped. Photos matched only via photoSlugs (not match patterns) are also excluded from the index. People with no qualifying solo photos do not appear on the index but still have individual person pages accessible via direct URL.

- Bio guidelines: omit bio for household names. Use achievement-first descriptors for less recognizable people (e.g., "Nobel Prize-winning physicist", "Dickinson, Anna and the Apocalypse"). Avoid generic labels like "Actor".

- To add a person: add entry to people.json, ensure matching photos exist in any gallery or highlights folder

​** Developer Notes

- Astro project uses import.meta.glob to dynamically load images

- All routes are filesystem-based

- No CMS: folder structure is the source of truth

- All content is static + light client-side JS (no SSR needed)

- Two gallery modes exist: YAML (src/gallery/gallery.yaml) and filesystem (src/gallery/photos/**). Avoid route conflicts; prefer one source per route.

- Packery is the homepage/folder-page masonry engine by deliberate choice (Jay, 2026-07-05). Do NOT propose replacing it with justified-layout or any other engine; the packery/imagesloaded/draggabilly dependencies stay.

- *Jay likes the desktop homepage.* Changes intended for phones belong inside the ~max-width~ blocks of [[file+emacs:/Users/jay/Dropbox/github/photos-jaydixit/src/pages/index.astro][📄 index.astro]]. Anything that alters desktop appearance must be flagged to him before it ships, and is worth verifying rather than asserting: build the pre-change tree from a stash, screenshot both, and pixel-diff.

- *Homepage mobile is a separate layout regime, not a squeezed desktop.* Below ~820px~ the hero neutralizes the desktop absolute positioning (~position: relative~, ~inset/top/left/width: auto~) and rebuilds the collage as three full-width lead prints followed by a four-up contact-sheet strip. Desktop's ~--print-x~ / ~--print-y~ / ~--print-width~ composition is never read at that width.

- *Hero prints must not overlap on mobile.* Negative margins on ~.hero-print~ (previously ~nth-of-type(4)~ and ~(6)~) land on the caption band and bury the subject's name. Overlap is a desktop-only device.

- *The mobile photo wall must not repeat hero photographs.* Cards whose Cloudinary public IDs already appear in ~heroPrintLayout~ remain in the 23-card desktop wall but are hidden below ~820px~ and excluded from the mobile PhotoSwipe sequence. The 17 visible mobile cards are numbered ~1~–~17~.

- *The mobile photo wall must stay in strict document order* — ~grid-auto-flow: row~ below ~820px~, never ~dense~. Holes are prevented by a uniform ~4 / 5~ media aspect plus full-width landscape beats at DOM children ~8~, ~13~, ~17~, ~22~, and ~23~, which are visible mobile positions ~3~, ~8~, ~11~, ~16~, and ~17~ after the six hero duplicates are hidden; Stephen Root, Ella Hunt, and Demis Hassabis follow Lisa Gilroy as positions ~13~–~15~, and the two separate Oslo torchlight-procession photographs close the wall as full-width positions ~16~ and ~17~. Changing either ~heroPrintLayout~ or ~wallPhotos~ can change the duplicate set and invalidates those indices.

- *Hero clothespins are data, not decoration.* Each entry in ~heroPrintLayout~ in [[file+emacs:/Users/jay/Dropbox/github/photos-jaydixit/src/pages/index.astro][📄 index.astro]] carries a ~pins~ array (~pos~ left/right/centre, ~tilt~, optional ~inset~); the markup renders one ~.clothespin~ per pin, and each counter-rotates its print through ~--pin-rot~ so it hangs near vertical. Two traps: a print that bleeds past the hero's right edge (Bateman–Law, Sweeney) needs a viewport-proportional inset or its pin drifts off canvas on wide screens, and a pin can never paint above a higher-stacked neighbouring print, so a pin on a lapped corner sits at the visible end of the top edge. Moving any print's ~x~ or stacking order means re-checking both.

- *The homepage header hides its inline nav below 1420px*, which is laptop territory and not only phones. The compact toggle plus ~[data-menu-panel]~ is the only navigation at those widths and must not be removed. Both the inline nav and the panel render from the single ~navLinks~ array in the frontmatter so they cannot drift, and ~.site-nav-primary~ scopes the inline-nav styling so it does not leak onto the panel.

- *Homepage weight measurements must come from a production build.* ~npm run dev~ reports roughly ~886KB~ of homepage JavaScript; the built site ships about ~54KB~ gzipped and correctly excludes Three.js on mobile. See [[file+emacs:/Users/jay/Dropbox/github/photos-jaydixit/docs/codebase-wisdom.org][📄 codebase-wisdom.org]].

- *The Google Fonts request asks for Newsreader italic at weight 300 only.* Requesting a single italic weight makes Google serve a static instance (~63KB~) rather than a variable font (~147KB~). Every italic in the built site computes to weight 300, so restoring italic 400 costs ~84KB~ on every page for no rendering gain. Verify with a computed-style check before changing it.

- *Responsive image ~sizes~ must be reasoned about at DPR 3.* The profile portrait renders at ~350~ CSS px on a phone, which asks for ~1050~ device px and therefore selects the ~1280w~ derivative, not the ~720w~ one. A derivative that wins at DPR 1–2 can be bypassed entirely on real phones.

- Photo Wall Packery must quantize both axes from the responsive `.grid-sizer`: `columnWidth` and `rowHeight` both reference it, and the hidden sizer keeps `aspect-ratio: 2 / 3`. This prevents mixed 1x1, 2x1, and 2x2 tiles from developing settled holes at wide viewports. Validate both sides of every breakpoint, ultrawide widths through 7680px, and a temporary future 9- or 10-column rule; see `docs/debug/packery-responsive-row-grid-drift.org`.

- Highlights are part of the real photo system: homepage and red-carpet pages also read from src/gallery/highlights/

- Shared metadata helpers now live in src/lib/seo.ts, and JSON-LD rendering is centralized in src/components/StructuredData.astro

- Page-level scripts that import npm packages must use hoisted Astro scripts so Vite bundles them. If built HTML leaves bare imports instead of a bundled /_astro/*.js asset, browser-side features like PhotoSwipe will break.

- Source .webp files in src/gallery/photos/** are derivative siblings of canonical source images. Exclude or dedupe them when building gallery-style source lists, or routes like src/pages/gallery/[...folder].astro can render duplicate photos.

- Coding conventions: Components are PascalCase.astro (e.g., PhotoGrid.astro), modules are camelCase.ts (e.g., galleryData.ts). Tailwind v4 utility-first CSS.

- Site-wide settings live in site.config.mts

- Tests: Vitest framework, tests live in src/data/__tests__/*.test.ts. Run with npm run test. Run npm run lint and npm run prettier before submitting.

- User preference: org-mode is preferred for docs. In org files, use ~...~ instead of backticks for inline code.
