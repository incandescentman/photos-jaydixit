​** Overview

This is a static photography portfolio site built with Astro, hosted on
Vercel at photos.jaydixit.com. It supports automatic gallery generation
from folders, responsive masonry layout, full-screen lightbox viewing,
keyword search, tag-based filtering, per-photo liking, per-person
portrait pages, and optional commenting via Giscus. All metadata is
derived from filenames, per-folder tags.json files, or the people.json
manifest.



​** Core Features



​*** 📁 Folder-Based Gallery Pages

- Gallery source photos live in src/gallery/photos/** folder
- Portrait and homepage highlight assets also live in src/gallery/highlights/

- Each subfolder becomes a separate gallery

- Example: src/gallery/photos/locarno-film-festival →
  /gallery/locarno-film-festival



​*** 🧱 Masonry Layout

- Pure CSS layout with column-count and break-inside: avoid

- Responsive grid that lazy-loads images



​*** 💡 Lightbox Viewer

- Main galleries and comparison pages use PhotoSwipe for full-screen viewing

- Some older components and experiments still reference GLightbox

- Full-size viewer with zoom and nav arrows



​*** 📑 Captions from Filenames

- Filenames like maria-bakalova_locarno_2024.jpg become:

  "Maria Bakalova at Locarno in 2024"

- Year is optional

- Displayed under each photo



​*** 🔍 Search and Tag Filtering

- Single search input filters by:

  - Subject name

  - Event name

  - Tags (from filename or tags.json)

- Tags also appear as clickable pills (AND logic)

- Search and tags can be used together for progressive narrowing



​*** 🏷 Tags System

- Tags extracted from:

  - Filenames (e.g. _rain-night)

  - Folder names (e.g. /locarno → "locarno")

  - Optional tags.json file per folder

- tags.json format:

  {

  "filename.jpg": ["tag1", "tag2"]

  }

- If tags.json exists, it overrides filename tags



​*** 👤 Portraits (Per-Person Pages)

- Each person in src/data/people.json gets a page at /portraits/[slug]

- Index page at /portraits/ lists all people alphabetically with sample photos

- people.json fields: slug, name, match (filename patterns), photoSlugs (optional explicit mappings), bio (optional), wikipedia (optional)

- Match logic: subject slug (part before first _ in filename) checked against match patterns

- Numbered variants supported: match pattern "jeremy" also matches "jeremy-3", "jeremy-11"

- For group photos and non-standard filenames, use photoSlugs for explicit file-to-person mapping (e.g., group-portrait_ana-de-armas-sydney-sweeney-ron-howard_2024)

- Photos scanned from both src/gallery/photos/ and src/gallery/highlights/; gallery sources preferred for dedup

- Highlight-only photos render without gallery detail links

- To add a person: add entry to people.json, ensure matching photos exist in any gallery or highlights folder


​*** ❤️ Likes

- Each photo displays a like button and live count

- Stored in Supabase photo_user_likes table:

  - photo_id: string (filename)

  - visitor_id: string

  - created_at: timestamp

- Uses Supabase anonymous access and row-level security

- /popular aggregates counts from photo_user_likes by photo_id

- Future: most-liked photos or tag analytics



​*** 💬 Giscus Comments

- Optional comment thread per gallery or per photo

- Uses GitHub Discussions via Giscus

- Enabled with Discussions on GitHub repo:

  incandescentman/jaydixit-photos



​*** ☁️ Cloudinary Integration

- Homepage images served from Cloudinary CDN (cloud name: dszpm7yps)

​** Developer Notes

- Astro project uses import.meta.glob to dynamically load images

- All routes are filesystem-based

- No CMS: folder structure is the source of truth

- All content is static + light client-side JS (no SSR needed)

- Two gallery modes exist: YAML (src/gallery/gallery.yaml) and filesystem (src/gallery/photos/**). Avoid route conflicts; prefer one source per route.

- Highlights are part of the real photo system: homepage and portrait pages also read from src/gallery/highlights/

- Page-level scripts that import npm packages must use hoisted Astro scripts so Vite bundles them. If built HTML leaves bare imports instead of a bundled /_astro/*.js asset, browser-side features like PhotoSwipe will break.

- Source .webp files in src/gallery/photos/** are derivative siblings of canonical source images. Exclude or dedupe them when building gallery-style source lists, or routes like src/pages/gallery/[...folder].astro can render duplicate photos.

- Coding conventions: Components are PascalCase.astro (e.g., PhotoGrid.astro), modules are camelCase.ts (e.g., galleryData.ts). Tailwind v4 utility-first CSS.

- Site-wide settings live in site.config.mts

- Tests: Vitest framework, tests live in src/data/__tests__/*.test.ts. Run with npm run test. Run npm run lint and npm run prettier before submitting.

- User preference: org-mode is preferred for docs. In org files, use ~...~ instead of backticks for inline code.
