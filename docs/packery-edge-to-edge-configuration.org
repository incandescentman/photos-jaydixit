* Working Contract

Desktop and tablet widths above 768px use Packery. The wrapper and Packery container must stay full-width:

- ~.portfolio-wrap~ uses ~width: 100%~ and no horizontal padding.
- ~.masonry-items~ uses ~width: 100%~, ~padding: 0~, ~margin: 0 auto~, and ~overflow-x: hidden~.
- ~initPackeryGallery~ keeps the default ~mobileBreakpoint = 768~.
- Packery uses ~columnWidth: '.grid-sizer'~, ~rowHeight: '.grid-sizer'~, ~gutter: 8~, ~percentPosition: false~, ~resize: false~, and ~initLayout: false~.
- ~.grid-sizer~ is an invisible, absolutely positioned measurement element with ~aspect-ratio: 2 / 3~. Its responsive width defines a regular column and its resulting height defines a regular row.

Mobile widths at 768px and below use the flex fallback. Packery is not initialized; CSS forces natural document flow with:

- ~.masonry-items~ as a column flex container.
- ~.masonry-item~ reset to ~position: relative~, ~width: 100%~, and ~height: auto~.
- ~.grid-sizer~ hidden.
- images at natural height with ~object-fit: contain~.

* Column Math

The key is not centering a fixed-width stage. The key is making the columns themselves fluid and gutter-aware.

For an ~N~-column row with an 8px Packery gutter:

- Regular item width is ~100% / N - 8px * (N - 1) / N~.
- Wide item width is ~200% / N - 8px * (N - 2) / N~.

That produces exact rows where:

- ~N~ regular items plus ~N - 1~ gutters equal 100% of the viewport.
- A wide item spans two regular columns plus the one gutter between them.

Current breakpoints:

- ~769px-1099px~: 3 columns, regular ~calc(33.333333% - 5.333333px)~, wide ~calc(66.666667% - 2.666667px)~
- ~1100px-1303px~: 4 columns, regular ~calc(25% - 6px)~, wide ~calc(50% - 4px)~
- ~1304px-1631px~: 4 columns, regular ~calc(25% - 6px)~, wide ~calc(50% - 4px)~
- ~1632px-1959px~: 5 columns, regular ~calc(20% - 6.4px)~, wide ~calc(40% - 4.8px)~
- ~1960px-2287px~: 6 columns, regular ~calc(16.666667% - 6.666667px)~, wide ~calc(33.333333% - 5.333333px)~
- ~2288px-2615px~: 7 columns, regular ~calc(14.285714% - 6.857143px)~, wide ~calc(28.571429% - 5.714286px)~
- ~2616px+~: 8 columns, regular ~calc(12.5% - 7px)~, wide ~calc(25% - 6px)~

Eight columns is the current design cap, not an engineering assumption about the largest possible monitor or future layout. The row geometry must continue to work if a later design adds 9-, 10-, or higher-column breakpoints.

These rules intentionally appear twice in [[file+emacs:/Users/jay/Dropbox/github/photos-jaydixit/src/pages/photo-wall.astro][src/pages/photo-wall.astro]]:

- inside the ~criticalStyles~ string, so first paint has the same geometry Packery will read
- inside the page-level ~<style is:inline>~ block, so the settled page keeps the same geometry

Keep both copies synchronized.

* Row Geometry

Responsive column math alone is not sufficient. The fixed 8px gutter makes raw aspect-ratio-derived outer heights differ slightly as columns widen. Without a row grid, an opening that looks one portrait tall can be a few pixels too short for Packery to reuse.

Packery therefore measures ~rowHeight~ from the same ~.grid-sizer~ it uses for ~columnWidth~. With the sizer's ~2 / 3~ aspect ratio, the intended packing spans are:

- regular: 1 column by 1 row
- wide: 2 columns by 1 row
- wide-tall: 2 columns by 2 rows

Do not replace this with a fixed pixel ~rowHeight~. The sizer must keep following the live responsive column width so the contract works across viewport sizes and future column counts. The full diagnosis and high-resolution verification are in [[file+emacs:/Users/jay/Dropbox/github/photos-jaydixit/docs/debug/packery-responsive-row-grid-drift.org][📄 /Users/jay/Dropbox/github/photos-jaydixit/docs/debug/packery-responsive-row-grid-drift.org]].

* Why Earlier Attempts Failed

The previous problem was trying to center or pad a fixed-width Packery stage while columns still used the historical 320px / 648px widths.

That can move the grid, but it cannot make four fixed columns fill an arbitrary viewport. The result was always some version of the same bug: a right-side empty band, mismatched left and right gutters, or a stage that collapsed when ~fitWidth~ interacted with Packery sizing.

The working solution changes the premise: the stage is full-width, and each Packery item gets a viewport-relative width that already accounts for the 8px gutters.

One more detail matters for polish: Packery's staggered first layout can briefly position items off to the right before the settled layout is perfect. Keeping ~overflow-x: hidden~ on ~.masonry-items~ prevents a transient horizontal scrollbar during that settle period.

* What Not To Change Casually

- Do not enable Packery ~fitWidth~ for this homepage layout.
- Do not reintroduce side padding on ~.portfolio-wrap~ or ~.masonry-items~ unless you also rework the column formulas.
- Do not remove ~overflow-x: hidden~ from ~.masonry-items~ unless you have verified there is no transient horizontal scroll during first layout.
- Do not change the mobile breakpoint in [[file+emacs:/Users/jay/Dropbox/github/photos-jaydixit/src/scripts/packeryGallery.ts][src/scripts/packeryGallery.ts]] without changing the CSS fallback threshold in [[file+emacs:/Users/jay/Dropbox/github/photos-jaydixit/src/pages/photo-wall.astro][src/pages/photo-wall.astro]].
- Do not remove the duplicated critical and settled CSS copies unless the homepage gets a single generated source for those rules.
- Do not remove ~rowHeight~ or the sizer's ~2 / 3~ aspect ratio while mixed 1-by-1, 2-by-1, and 2-by-2 tiles share the Packery grid.
- Do not leave experiment metadata on the homepage. Canonical must be ~/~, title must be ~Red Carpet Highlights~, and the homepage must not set ~noindex~.
- Do not propose replacing Packery. Packery is the deliberate homepage and folder-page masonry engine.
